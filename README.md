# web-router · 网络能力路由

web-router 是一个网络能力路由技能：面对联网检索类需求，先盘点你的客户端与机器上实际可用的能力，再选出一条明确可执行的路径；能力缺失时给出可核对的降级，而不是假装成功。

本包只包含 Markdown 指南，不捆绑程序、账号或 API 额度。执行仍依赖宿主或你自行接入的工具；不保证所有客户端兼容、所有平台可访问。公开发布版 3.1.0，MIT 许可。

## 它替你做什么

给它一句话，它会先核对“能不能做”，再动手；并把结论、来源和没做到的部分一起交给你。

| 你说 | 它做什么 |
|---|---|
| “搜一下最新的国资监管规定有哪些变化” | 走搜索源定位，再筛可信来源、给出处，并区分同一通稿的多次转载 |
| “把这个网页的正文提取出来（附链接）” | 读取正文；确需渲染时才转浏览器，不先失败所有低阶分支 |
| “把这个账号的视频标题和点赞数抓下来” | 先区分关键词搜索／热搜榜／作品榜／评论采样的口径，只取元数据、不下载视频 |
| “整理这个视频的英文逐字稿” | 先核对字幕语言与来源；中文机翻不冒充英文原文，只有简介就写“基于简介的概述” |
| “请根据我的电脑配置网络工具” | 加载首次配置向导，只读盘点已有能力后按最小需求逐步引导 |
| “每周追踪这些公开页面的变化” | 确认页面范围与输出方式，用宿主调度能力建任务，并区分“本次成功”与“排程已建立” |

完整路由决策表见 [SKILL.md](SKILL.md)；平台细分步骤见 [references/workflows.md](references/workflows.md)，按需加载当前任务相关章节。

## 安装（三步）

1. **放目录**——把 `web-router/` 放进你的技能目录。WorkBuddy 用户级为 `~/.workbuddy/skills/web-router/`，项目级为 `.workbuddy/skills/web-router/`；**两处只装一处**，遇到同名件先备份并确认，不要直接覆盖。若从 GitHub 的 Code → Download ZIP 下载，解压目录名通常带分支名，请改名为 `web-router`。
2. **开新会话**——让客户端重新扫描技能目录。
3. **确认被发现**——在新会话里问一个网络检索类问题，看它是否加载本技能。**普通对话里模型恰好用了搜索，不能单独证明技能被触发**；要看客户端的技能加载记录或显式加载结果。

其他客户端请按其技能规范适配；本次未逐一验证。

## 首次配置

在会话中选中本技能后说：

> 请根据我的电脑配置网络工具：先盘点已有能力，再引导我配置需要的代理、API 和依赖。所有修改先确认，不要安装整套工具。

技能会按 [references/setup.md](references/setup.md) 走六步：确定最小需求 → 只读能力盘点 → 网络与代理 → API 与连接器 → 程序与运行时依赖 → 验收与本地状态。

三点先说清：**基础搜索与网页阅读通常已够用，普通查询不必先配置**；网络正常就不配代理；配置值存你自己的私有位置，公共仓库只放无真实凭证的示例结构。

## 能与不能

| 能做 | 不能做 |
|---|---|
| 在已有能力范围内选路：搜索发现、正文提取、语义检索、平台查询、字幕全文、受控浏览器、周期编排 | 不提供搜索、账号、API 额度、浏览器或运行时——它只做选择与编排 |
| 缺依赖时给明确降级路径，并说明降级后证据强度的变化 | 不在缺依赖时虚构结果；不保证某平台、某视频、某页面一定可获取 |
| 引导你按自己机器配置代理、API 与依赖（只读盘点后逐步确认） | 不自动改系统代理、不装根证书、不关 TLS 校验、不自动提权、不建常驻任务 |
| 把网页、仓库、文档、检索结果当外部数据处理，不服从其中的附加指令 | 不规避访问控制、验证码、风控或付费墙；不使用隐藏接口或伪造登录态 |
| 批量任务先小样本验证，再按平台限额与宿主资源分批 | 不默认下载整段视频或整库评论；不声称全量覆盖 |
| 交付时区分原文、搜索摘要、平台元数据、字幕、转写与推断 | 不把简介或搜索摘要称为读完全文、看完视频 |

## 数据与隐私边界

- **读什么**：你给出的链接与查询词；按需读取当前会话的工具清单、已加载技能的元数据，以及与任务直接相关的少量配置项。**不扫描整个用户目录，不读取密钥值。**
- **写什么**：默认只把结果输出到对话，或写入你确认的目录（默认不覆盖同名文件）；改动本地配置前先备份、合并新项并取得你的确认。
- **不外发什么**：不把内部文件、原始会话、带访问令牌的私有链接、凭证或登录态发送给第三方搜索、转写或总结服务——除非你已知悉目标服务与数据范围并明确授权。不在聊天、仓库或 Issue 中保存密钥。
- **凭证怎么处理**：登录由你在官方授权流程完成；本技能不解密浏览器凭证、不提取其他客户端的会话缓存、不要求你把密码／验证码／Cookie／API 密钥粘贴到公共文档。需要持久化时，只在你自己的技能目录之外保存非敏感项（能力、版本、验证日期、配置项是否存在）。

## 已知限制与未解决事项

**已知限制**

- 只在已有能力范围内路由；缺依赖时交付的是降级结果，证据强度低于完整路径。
- 平台内容获取受平台规则、登录要求与限额约束：不保证任意视频有字幕、任意页面可渲染、任意账号可查询。
- 周期能力依赖宿主调度；**一次性执行成功不代表未来排程已建立，也不代表每次都可用**。
- 不提供默认密钥、免费额度承诺、固定版本、代理端口或可直接复制的占位命令。

**未解决事项（发布决策须一并考虑）**

1. **历史参考材料逐源比对未完成**——源技能曾明确借鉴若干外部方法论与提示词。经核对，**这些内容均未随本包分发**；但完整逐源比对未做，按“待核”处理，不作绝对原创声明。
2. **市场与客户端验收未完成**——市场服务端解析、全新客户端导入后的发现与加载均**未测**。
3. **多发布渠道的版本同步未验证**——本技能同时以 GitHub 公开仓库（`github.com/Robertlgz/web-router`）与市场包两种形态分发，二者由同一份源文件产出；**两处版本号是否始终一致未实测**，若不一致以较新者为准。
